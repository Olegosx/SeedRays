# ADR-0008: Общая реестровая база данных

**Статус:** принято; дополнено [ADR-0010](0010-networks-assets-financial-data.md) — в реестре
также живут справочник активов и служебное состояние watcher по сетям

## Контекст

При базах на пользователя ([ADR-0005](0005-multi-user-model.md)) общешлюзовым данным негде
жить: поиск пользователя по логину при входе, мгновенное определение владельца API-ключа,
учётные записи операторов, общие настройки шлюза (интервалы watcher, ключи доступа к
провайдерам данных — например, один ключ TronGrid на весь шлюз). Раскладывать это по
пользовательским базам означало бы перебирать N баз на каждый поиск или зашивать индекс в
соглашения об именовании каталогов.

## Решение

Шлюз ведёт одну небольшую общую базу с реестровой ролью:

- реестр пользователей: идентификатор, статус, учётные данные для входа, ссылка на каталог
  пользователя;
- индекс API-ключей: хеш ключа → пользователь-владелец;
- учётные записи операторов (суперадминов);
- общие настройки шлюза.

Финансовых данных в ней нет: кошельки, адреса, привязки и операции живут только в
пользовательских базах.

## Рассмотренные альтернативы

- **Совсем без общей базы** (поиск логина по именам каталогов, идентификатор пользователя
  внутри API-ключа): работоспособно, но это изобретение реестра, размазанного по соглашениям
  файловой системы; отклонено.
- **Одна общая база для всего:** уже отклонено в [ADR-0005](0005-multi-user-model.md) —
  структурная изоляция данных пользователей.

## Последствия

- Вход и определение владельца ключа — один запрос к реестру, затем открытие единственной
  нужной пользовательской базы.
- Компрометация или порча реестра не раскрывает платёжные данные; пользовательская база
  остаётся самодостаточной единицей резервного копирования и переноса.
- Схема реестра мигрирует отдельно от схемы пользовательских баз.
