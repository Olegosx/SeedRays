# ADR-0017: Универсальная модель транзакций — две таблицы по физическому местоположению

**Статус:** принято

## Контекст

Трёхтабличная модель [ADR-0010](0010-networks-assets-financial-data.md)
(неподтверждённые / подтверждённые / неуспешные) смешала физически разные вещи. У
транзакции ровно два физических местоположения: **очередь** (мемпул — разослана, но ни в
какой блок не попала; в EVM-сетях транзакция с низкой комиссией может висеть там часами) и
**блокчейн** (попала в блок). У транзакции в блоке две **независимые** характеристики:
**результат исполнения** (успех — или провал вроде REVERT / нехватки энергии: транзакция
навсегда в блокчейне, комиссия сгорела, но перевод не произошёл) и **окончательность**
(вычисляемая граница — у TRON солидификация, — а не состояние). Старая таблица
«неподтверждённых» подменяла очередь на «в блоке, но ждёт финальности», а «неуспешные»
возводили атрибут в сущность. Модель обязана быть универсальной для всех сетей.

## Решение

- **`transactions`** — только транзакции в блокчейне: адрес, ид транзакции, актив,
  направление, сумма, **номер блока (обязателен)**, время, **статус исполнения
  (успех / провал)**, время первой встречи и служебная отметка **«учтена в балансе»** —
  ставится ровно один раз, в той же транзакции БД, что и обновление баланса. В остальном
  строки только добавляются.
  - Подтверждённость / ожидание финальности — **вычисляется** от границы финальности
    сети, никогда не хранится.
  - Провальные строки на балансы не влияют никогда; хранятся для разбора споров
    («я оплатил, вот хеш» — а по хешу видно провал исполнения).
  - Идемпотентность: уникальный ключ «ид транзакции + адрес + актив».
- **`mempool_queue`** — наблюдения очереди: без номера блока; строки могут висеть или
  исчезать. Универсальная сущность модели: наполняется только там, где источник данных
  сети видит очередь (проиндексированные провайдеры TRON — нет; источники EVM и свои
  ноды — да).
- **`balances`** — остаётся кэшированным агрегатом из
  [ADR-0010](0010-networks-assets-financial-data.md), обновляется в одной транзакции БД с
  отметкой.

## Рассмотренные альтернативы

- **Прежние три таблицы:** отклонено — перекладывание строк между таблицами моделирует
  вычисляемую границу движением данных, а «провал» — атрибут, не сущность.
- **Совсем без таблицы очереди:** отклонено — очередь физически реальна в EVM-сетях, а
  модель обязана быть универсальной.
- **Полностью вычисляемые балансы без кэша:** на наших объёмах работало бы, но
  отклонено — дешёвые массовые чтения балансов приложениями остаются требованием.

## Последствия

- Схема пользовательской базы перерабатывается до первого выпуска (исходная миграция
  переписывается — развёртываний нигде не существует).
- Watcher классифицирует строки по границе, а не перекладывает их между таблицами.
- Предварительным строкам, так и не достигшим финальности (перестройки цепочки), нужна
  политика чистки — определяется при реализации watcher.
