# ADR-0003: Один процесс бэкенда с оркестратором-надсмотрщиком

**Статус:** принято

## Контекст

В бэкенде две долгоживущие активности: HTTP API-сервер и watcher. Им нужна определённая
независимость: сбой одной не должен останавливать другую. Шлюз позиционируется как лёгкий,
поэтому простота эксплуатации важна.

## Решение

Бэкенд работает одним процессом. При старте оркестратор запускает API-сервер и watcher
параллельно (потоками или асинхронными задачами) и присматривает за обоими: сбой
записывается в журнал, упавший компонент перезапускается, второй продолжает работать.

## Рассмотренные альтернативы

- **Отдельные процессы для API и watcher:** даёт настоящую независимость на уровне
  процессов, но добавляет межпроцессное взаимодействие и утяжеляет развёртывание; для старта
  отклонено как противоречащее «лёгкому» позиционированию. Оставлено как заготовленный путь
  эволюции — модульная структура (см. [ADR-0001](0001-library-first-core.md)) делает будущее
  разделение дешёвым.

## Последствия

- Изоляция сбоев — на уровне логики, не процессов: если умирает весь процесс, умирают оба
  компонента.
- Развёртывание и эксплуатация остаются простыми: один процесс бэкенда.
- Будущее разделение на два процесса не потребует переделки компонентов.
