# ADR-0012: Стек фронтенда — статика без сборки с завендоренными библиотеками

**Статус:** принято

## Контекст

Фронтенд — это кабинет пользователя и панель оператора: формы, таблицы с серверной
пагинацией, периодическое обновление цифр. Шлюз — софт финансового сектора: цепочка
поставки стороннего кода должна быть минимальной и аудируемой, а развёртывание возможно в
закрытом контуре без доступа в интернет. Граница «фронт общается с бэкендом только через
HTTP API» зафиксирована архитектурой.

## Решение

- **Чистая статика, без сборки, без Node.js**: HTML, CSS и современный JavaScript
  ES-модулями (браузеры поддерживают нативно). Что лежит в репозитории — то и исполняется
  в браузере.
- **Многостраничная структура**: каждый экран — свой HTML-файл; общий код — в ES-модулях;
  клиентского маршрутизатора нет.
- **Доступ к API — встроенным `fetch`** браузера; фронт использует только API пользователя
  и API оператора.
- **Комплект интерфейса: Tabler** (внутри — Bootstrap 5) с **Tabler Icons**; клиентская
  интерактивность: **Alpine.js**. Все три — под лицензией MIT (Tabler и Tabler Icons
  проверены по их репозиториям, август 2026).
- **Политика вендоринга**: каждая сторонняя библиотека — просмотренный файл фиксированной
  версии в репозитории (`frontend/vendor/`), рядом — текст её лицензии; никаких CDN в
  проде; обновление библиотеки — осознанная отдельная задача.
- **Суммы остаются строками** в JavaScript (API отдаёт их строками); любая арифметика —
  только через BigInt.

## Обоснование безопасности

- **Атаки через цепочку поставки в реестрах пакетов — регулярная реальность**:
  `event-stream` (2018 — в популярную библиотеку внедрили код кражи криптокошельков),
  `ua-parser-js` (2021 — захват учётной записи мейнтейнера), `node-ipc` (2022 —
  разрушающий код, добавленный самим мейнтейнером). Типичный собираемый фронт тянет сотни
  неаудируемых транзитивных зависимостей; наш стек сводит цепочку к нескольким
  просмотренным файлам.
- **Сборочный конвейер — тоже софт, которому надо доверять**: npm-пакеты умеют выполнять
  произвольные скрипты при установке; сборщики и их плагины исполняют код на машинах
  разработчиков и в CI. Нет сборки — этого класса угроз не существует в принципе.
- **Аудируемость**: никаких трансформаций между исходником и поставкой; поверхность
  проверки для аудита безопасности мала и читаема.
- **Развёртывание в закрытом контуре**: для поставки не нужны ни реестр пакетов, ни
  сборочная инфраструктура — папка статики, которую раздаёт что угодно, включая сам
  процесс бэкенда.

## Рассмотренные альтернативы

- **SPA на инструментарии Node (Vue/React/Svelte + Vite):** отклонено — дерево зависимостей
  и сборочная инфраструктура противоречат требованиям к цепочке поставки, а компенсирующей
  необходимости нет: интерфейс — формы и таблицы.
- **Серверный рендеринг внутри бэкенда (Jinja2 + htmx):** отклонено — размывает
  зафиксированную границу «фронт ↔ только HTTP API».
- **Отдельный фронт-сервис на Python (Jinja2 + htmx + Alpine.js):** работоспособно и
  границу сохраняет, но добавляет второй сервис; отклонено в пользу ещё меньшего числа
  подвижных частей.
- **NiceGUI (интерфейс, описываемый на Python):** отклонено — глубокая привязка к нишевому
  инструменту с упакованным чужим клиентским стеком и websocket-каналом вне нашего
  контроля.

## Последствия

- Таблицы, формы и связующий код страниц пишутся руками; TypeScript отсутствует — ошибки
  всплывают в браузере, поэтому дисциплина кода и тесты весят больше.
- Обновления безопасности завендоренных библиотек — ручная обязанность: отслеживание
  уязвимостей Tabler/Bootstrap/Alpine.js и обновление файлов — пункт регламента
  сопровождения.
- Фронт работает офлайн и в закрытых контурах; раздавать его может любой сервер статики.
