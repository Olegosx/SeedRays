# ADR-0001: Ядро-библиотека с тонкими обёртками

**Статус:** принято

## Контекст

Три функции шлюза (генерация ключа, деривация, наблюдение) должны быть доступны несколькими
способами: автономно из терминала, внутри оркестратора и в тестах. Реализация каждой точки
входа по отдельности привела бы к дублированию логики.

## Решение

Вся бизнес-логика живёт в импортируемых Python-модулях с чистыми интерфейсами. Каждая точка
входа — консольные команды, HTTP API-сервер — лишь тонкая обёртка, которая переводит свой
транспорт (аргументы командной строки, HTTP-запросы) в вызовы этих модулей.

## Рассмотренные альтернативы

- **Логика внутри точек входа** (команды и HTTP-обработчики владеют своей логикой):
  отклонено — ведёт к дублированию и расхождению поведения между командной строкой и API,
  а ядро становится нетестируемым без транспорта.

## Последствия

- Один код обслуживает командную строку, оркестратор и тесты.
- Ядро тестируется без HTTP и терминала.
- Новые интерфейсы (например, другой транспорт) добавляются, не трогая логику.
