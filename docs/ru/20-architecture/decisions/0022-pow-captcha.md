# ADR-0022: Анонимные маршруты аутентификации за самодостаточной proof-of-work капчей (ALTCHA)

**Статус:** принято

## Контекст

Анонимные маршруты аутентификации (вход, регистрация, запрос сброса пароля, вход
оператора) защищены только тормозом перебора в памяти процесса. Тормоз ограничивает
частоту попыток, но сама попытка бесплатна; распределённый атакующий со множеством
адресов обходит поклиентские окна. Капча добавляет цену каждой попытке. Внешние
сервисы капчи (reCAPTCHA, hCaptcha, Turnstile и второй эшелон — GeeTest, MTCaptcha,
Friendly Captcha, CaptchaFox) требуют регистрации каждой установки и зависимости от
третьей стороны, что противоречит самоустанавливаемой природе шлюза; обзор рынка
выполнен 2026-09-07.

## Решение

- **Подтверждение работы вместо головоломок**: браузер в фоне решает небольшую задачу
  на вывод ключа (ALTCHA, PBKDF2/SHA-256, стоимость 10 000, ~0,5 с процессорного
  времени на попытку); посетитель ничего не видит и не вводит. Proof-of-work не
  отличает человека от бота — он назначает цену попытке; это второй слой поверх
  тормоза перебора, а не его замена.
- **Полностью самодостаточно**: задачи выдаёт и проверяет сам шлюз
  (`GET /v1/user/captcha`, `GET /v1/operator/captcha`); без внешнего сервиса,
  регистраций и запросов, покидающих установку. Виджет (MIT) вендорится по правилам
  [ADR-0012](0012-frontend-stack.md); серверная часть — официальная Python-библиотека
  `altcha` (MIT, без зависимостей).
- **Подписанные задачи без состояния**: каждая задача несёт срок годности (10 минут) и
  подпись HMAC; ключ подписи случаен на процесс и живёт только в памяти. Решения
  одноразовые — реестр использованных одноразовых меток (nonce) живёт в памяти процесса
  с той же честной однопроцессной семантикой, что и тормоз перебора
  ([ADR-0003](0003-single-process-supervised.md)): нечего настраивать, ничего в базе,
  перезапуск лишь заставит браузеры решить свежую задачу.
- **Покрытие**: вход, регистрация, запрос сброса пароля, вход оператора — изменяющие
  анонимные маршруты. Подтверждение сброса уже защищено одноразовым токеном из письма.
  Проверка идёт после тормоза перебора (самая дешёвая защита — первой) и до любой
  бизнес-логики; отказ отвечает 400 `captcha_failed`.

## Рассмотренные альтернативы

- **Внешние сервисы капчи** (reCAPTCHA, hCaptcha, Turnstile, Friendly Captcha, GeeTest,
  MTCaptcha, CaptchaFox, Yandex SmartCaptcha): все требуют регистрации сайта и ключей и
  отдают трафик посетителей третьей стороне; отклонены для самоустанавливаемого шлюза.
- **Cap** (Apache 2.0, proof-of-work): сервер проверки — JavaScript (рантайм Bun) —
  чужеродный сервис рядом с Python-бэкендом; отклонён.
- **mCaptcha** (Rust, AGPL): не дошёл до версии 1.0, редкие релизы; отклонён.
- **Классические картиночные капчи** (Python-генераторы): уверенно решаются
  современными моделями зрения и при этом раздражают людей; отклонены.

## Последствия

- Вход требует JavaScript с Web Crypto API (криптография в браузере: браузеры 2018 года
  и новее); для кабинета платёжного шлюза приемлемо.
- Одна проверка стоит серверу ~2 мс (быстрый путь по HMAC); браузер тратит долю секунды
  на попытку — незаметно за состоянием загрузки кнопки.
- Виджет — четвёртая вендоренная библиотека; её обновление — осознанная отдельная
  задача (ADR-0012).
- Тесты решают настоящие задачи с пониженной стоимостью (явный параметр `create_app`);
  криптографический путь тот же.
