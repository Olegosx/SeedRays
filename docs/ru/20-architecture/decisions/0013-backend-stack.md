# ADR-0013: Стек бэкенда

**Статус:** принято

## Контекст

Начинается реализация бэкенда. Шлюз — софт финансового сектора: валидация входных данных —
вопрос безопасности, список зависимостей должен быть коротким и осознанным, а
криптографические библиотеки — самое ответственное решение проекта. Факты проверены по
первоисточникам (GitHub/PyPI, август 2026): bip-utils 2.12.2 от 13.08.2026 (MIT,
BIP39/32/44 и адреса 100+ монет, включая TRON и Ethereum); coincurve 21.0.0 (обёртка над
libsecp256k1 — аудированной C-библиотекой Bitcoin Core; используется Ethereum и libp2p);
mnemonic 0.21 (эталонная реализация BIP39 от Trezor). Целевая машина: Ubuntu 26.04 LTS,
системный Python 3.14.4.

## Решение

- **Python 3.14** — системный интерпретатор текущей Ubuntu LTS; проект работает в
  виртуальном окружении, в систему ничего не устанавливается.
- **FastAPI + uvicorn** — веб-фреймворк: декларативная валидация pydantic каждого входного
  поля до попадания в логику (для финансового API это защита, а не удобство);
  автоматическая OpenAPI-спецификация — бесплатная, всегда актуальная документация API для
  разработчиков приложений; асинхронность ложится на однопроцессную модель
  [ADR-0003](0003-single-process-supervised.md) с watcher как фоновой задачей.
- **SQLAlchemy Core + Alembic** — слой БД: один код запросов на SQLite/PostgreSQL/MySQL
  (ровно план [ADR-0006](0006-storage-abstraction.md), чей открытый вопрос о библиотеке
  этим закрывается); Alembic ведёт миграции, включая цикл по N пользовательских баз.
  Именно Core, не ORM: явные запросы без магии объектных отображений.
- **httpx** — асинхронный HTTP-клиент к провайдерам данных цепочек. REST-интерфейсы
  провайдеров вызываются напрямую за нашей собственной абстракцией цепочек; библиотеки-
  обёртки (например, tronpy) не используются.
- **bip-utils** — BIP39/BIP32/BIP44 и кодирование адресов TRON/EVM. Версия фиксируется;
  официальные тестовые векторы BIP39/BIP32/BIP44 входят в наш тестовый набор как страховка —
  любая поломка или подмена мгновенно валит тесты. Примечание: на 2.12.2 автор заявляет в
  классификаторах Python до 3.13; корректность на 3.14 проверяется теми же векторами.
- **argon2-cffi** — хеширование паролей входа в кабинет/оператора (Argon2 — победитель
  конкурса Password Hashing Competition, текущая рекомендация для новых систем).
- **argparse** (стандартная библиотека) — консольные команды; ноль зависимостей на нашем
  масштабе CLI.
- Версии зависимостей фиксируются в `pyproject.toml` при создании окружения; обновление
  зависимости — осознанная отдельная задача.

## Рассмотренные альтернативы

- **Flask** — минимализм, но синхронный и с ручной валидацией финансовых входов; отклонено.
  **aiohttp** — асинхронный и самодостаточный, но без слоя валидации и без генерации
  OpenAPI; отклонено.
- **Свой слой БД над драйверами** — ноль зависимостей, но три SQL-диалекта и машинерия
  миграций на руках; отклонено.
- **Минимальные криптокирпичи** (mnemonic + coincurve + собственная реализация BIP32/44) —
  каждый кирпич безупречен по репутации, но код деривации пишем сами: для финансового
  продукта «не пиши свою криптографию» перевешивает лишнюю зависимость; отклонено.
- **tronpy и подобные обёртки цепочек** — чужая обёртка внутри нашей абстракции добавляет
  зависимость без пользы; отклонено.
- **bcrypt** — работает, но стандарт прошлого поколения рядом с Argon2; отклонено.
- **click/typer** — сверх argparse на нашем масштабе не дают ничего; отклонено.

## Последствия

- Семь боевых зависимостей на весь бэкенд: fastapi, uvicorn, sqlalchemy, alembic, httpx,
  bip-utils, argon2-cffi (pytest — в dev-группе).
- Риск «одного мейнтейнера» у bip-utils компенсируется фиксацией версии и стандартными
  тестовыми векторами.
- Код бэкенда — асинхронный насквозь (FastAPI + httpx + задачи watcher).
