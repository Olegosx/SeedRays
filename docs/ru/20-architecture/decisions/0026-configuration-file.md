# ADR-0026: Конфигурационный файл как развёрточный уровень

**Статус:** принято; частично пересматривает [ADR-0016](0016-config-layers.md) — развёрточный
уровень переезжает из переменных окружения в файл, а само разделение конфигурации на два
уровня остаётся прежним

## Контекст

[ADR-0016](0016-config-layers.md) разделил конфигурацию шлюза надвое: развёрточный уровень —
то, что процессу нужно до открытия какой-либо базы, — и таблица `settings` реестра, которой
оператор управляет на ходу. Это разделение верно и здесь под сомнение не ставится.

Под сомнением носитель нижнего уровня. ADR-0016 взвесил ровно две альтернативы — «всё в
переменных окружения» и «всё в базе данных», — и конфигурационного файла среди них не было.
То есть выбор переменных окружения опирается на довод против базы данных, а не на сравнение с
тем вариантом, который принимает эта запись.

При этом сам ADR-0016 относит к этому уровню будущую строку подключения к PostgreSQL, а в ней
будет пароль. Проверено на живой системе Linux: unit-файлы в `/etc/systemd/system` по
умолчанию читаемы всем (`-rw-r--r-- root root`), а `systemctl show <юнит> -p Environment`
печатает окружение юнита непривилегированному пользователю. Значит, пароль в `Environment=`
доступен любому, у кого есть доступ к консоли сервера.

## Решение

- **Развёрточный уровень — файл TOML `seedrays.toml`.** В нём каталог данных, адрес привязки
  API, каталог статики фронтенда, а с переходом на PostgreSQL — строка подключения к реестру.
- **Переменные окружения перестают быть источником конфигурации вовсе.** `SEEDRAYS_DATA_DIR`,
  `SEEDRAYS_BIND` и `SEEDRAYS_FRONTEND_DIR` удаляются, а не остаются переопределением:
  механизм, которого нет, не может случайно утечь паролем.
- **Два места поиска по очереди**: `seedrays.toml` в копии репозитория, затем
  `/etc/seedrays/seedrays.toml`. Побеждает первый найденный, и **прочитанный файл печатается
  в журнал при старте** — при двух местах оператор не должен гадать, какой из них выиграл.
- **Аргумент `--config <путь>` перекрывает поиск** у команд, работающих с данными шлюза. Это
  аргумент командной строки, а не переменная окружения: в `systemctl show` он не появляется,
  дочерним процессам не наследуется и несёт путь, а не секрет. Именно он позволяет держать на
  одной машине несколько шлюзов с разными каталогами данных.
- **TOML, а не JSON**, потому что файл правят руками на сервере, а JSON не умеет комментариев:
  пояснение к каждой настройке пришлось бы держать где-то ещё, а это обесценивает саму идею
  «одного очевидного места». `tomllib` входит в стандартную библиотеку с Python 3.11, поэтому
  формат не стоит ни одной зависимости.
- **Относительный путь считается от каталога, где лежит конфиг**, а не от текущего рабочего
  каталога: иначе одно и то же значение означало бы разные места в зависимости от того, откуда
  запущен процесс. На сервере используются абсолютные пути.
- **Неизвестный ключ — ошибка с именем ключа**, а не молча пропущенная строка: та же
  строгость, которую панель оператора уже применяет к неизвестной настройке.
- Обязателен только каталог данных. Адрес привязки по умолчанию — `127.0.0.1:8080`, каталог
  статики по умолчанию — `frontend/` той копии репозитория, из которой запущен пакет.

## Рассмотренные альтернативы

- **Переменные окружения (прежнее решение):** отклонено — пароль в `Environment=` юнита
  читается любым пользователем сервера (проверено, см. контекст), а конфигурация шлюза
  оказывается внутри файла управления процессом вместо собственного места. Единственное их
  реальное преимущество — удобство в контейнерах — этого не стоит.
- **Оставить переменные как переопределение поверх файла:** отклонено решением владельца —
  один источник правды и ни одного механизма, через который строка подключения могла бы
  случайно попасть в окружение.
- **JSON:** отклонено — нет комментариев, а файлу, который правят руками во время инцидента,
  они нужны. JSON5/JSONC это лечат ценой новой зависимости.
- **INI через `configparser`:** работоспособно и привычно администраторам, но все значения
  там строки и вложенности нет — жидковато под строку подключения и под то, во что файл
  вырастет.
- **Одно место поиска вместо двух:** отклонено — локальный файл делает разработку
  самодостаточной, а `/etc/seedrays/seedrays.toml` — то место, куда администратор сервера
  посмотрит первым. Цена — риск ниже.

## Последствия

- Развёртываний пока не существует, поэтому переносить нечего: ломающее изменение, ломать
  которым некого.
- Документ развёртывания упрощается: один прокомментированный файл вместо таблицы переменных
  и строк `Environment=` в юните systemd.
- **Забытый в каталоге кода `seedrays.toml` на сервере молча перебьёт `/etc`.** Смягчения: в
  репозиторий коммитится только `seedrays.example.toml`, настоящий файл внесён в
  `.gitignore`, а журнал при старте называет прочитанный файл.
- Файл должен быть читаем только служебным пользователем (`chmod 600`), как только в нём
  появится пароль к базе.
- Чтение конфигурации остаётся в одной точке на границе процесса: `cli.py` разрешает её и
  передаёт вниз обычные значения. Ничто ниже точки входа не знает, что конфигурационные файлы
  существуют, — это принцип тонкой обёртки из [ADR-0001](0001-library-first-core.md).
