# ADR-0007: Адресоцентричный проход watcher

**Статус:** принято

## Контекст

При нескольких пользователях watcher должен наблюдать кошельки всех. Лимиты запросов у
провайдеров данных — общие на весь шлюз (провайдер считает запросы по IP/ключу независимо от
того, чьи адреса спрашивают), часть провайдеров умеет пакетные запросы, и ни один
пользователь не должен вытесняться большим набором адресов другого.

## Решение

Watcher мыслит адресами, а не пользователями. Перед проходом он собирает со всех
пользователей единый рабочий список отслеживаемых адресов, каждый помечен владельцем
(пользователь, кошелёк) и цепочкой. Проход обрабатывает список с группировкой по цепочке и
провайдеру, с централизованным управлением частотой запросов по каждому провайдеру и
справедливым порядком между пользователями. Ошибки изолируются на уровне адреса/пользователя
внутри прохода. Результаты раскладываются по базам владельцев.

## Рассмотренные альтернативы

- **Цикл по пользователям с поочерёдной проверкой адресов каждого:** отклонено — пакеты
  запросов мельче, нет централизованного управления лимитами провайдера, а время прохода
  растёт с числом пользователей независимо от числа адресов.
- **Фоновая задача на пользователя:** отклонено — независимые задачи совместно превышают
  общие лимиты провайдера, справедливость не решается без дополнительного планировщика,
  сложность растёт с числом пользователей.

## Последствия

- Управление лимитами и пакетность живут в одном месте — по провайдеру.
- Watcher остаётся единым контролируемым компонентом (согласуется с
  [ADR-0003](0003-single-process-supervised.md)); «задача на цепочку» — естественная
  следующая ступень, если цепочек станет много.
- О пользователях знает только шаг сбора рабочего списка; сам проход от них не зависит.
