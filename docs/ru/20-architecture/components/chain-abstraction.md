# Абстракция блокчейна

Интерфейс «источник данных цепочки», отделяющий [watcher](watcher.md) и остальной бэкенд от
конкретного способа доступа к блокчейну.

## Назначение

- Первые реализации работают через публичные API провайдеров; последующий переход на свою
  развёрнутую ноду (RPC) не должен затрагивать логику компонентов над абстракцией.
- На каждую цепочку — своя реализация в `chains/` (например, `tron/`).

## Поддерживаемые цепочки

Сначала TRON; далее ETH, TON и другие. TRON обслуживается через TronGrid с сетевыми кодами
`tron` (боевая) и `tron-nile` (тестовая; включается только явной конфигурацией
оператора) — см. [ADR-0015](../decisions/0015-tron-provider.md).

## Интерфейсы

Интерфейс «источник данных цепочки» даёт:

- `latest_block()` — текущая высота сети;
- `transfers(адрес, с_момента, только_подтверждённые)` — нормализованные события переводов
  по одному адресу: ид транзакции, направление, сетеспецифичный актив (символ,
  десятичность — корм справочника активов), сумма в минимальных единицах, номер блока,
  когда он сообщён, время и успех/провал. Используется для точечных задач: первичная
  история привязки, выборочная сверка.
- **Диапазонные операции** — основной съём по
  [ADR-0018](../decisions/0018-range-scanning.md): граница финальности, события Transfer
  токен-контракта за диапазон времени/блоков, нативные переводы диапазона блоков.

Ответы провайдера «сбавь темп» (HTTP 429/403) всплывают отдельной ошибкой ограничения
частоты, отличимой от ошибок данных; политика выжидания — забота [watcher](watcher.md).
