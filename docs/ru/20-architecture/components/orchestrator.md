# Оркестратор

Сервисный слой бэкенда: в нём живёт бизнес-логика, он координирует функциональные компоненты.

## Назначение

- Предоставляет операции шлюза («выдать адрес под платёж», «отдать поступления и балансы», …)
  как чистый программный интерфейс. [HTTP API](http-api.md) и консольные команды — тонкие
  обёртки над этим интерфейсом.
- Вызывает [генератор ключа](key-generator.md), [модуль деривации](derivation.md) и
  [watcher](watcher.md) как обычные Python-модули.
- При старте запускает HTTP API-сервер и watcher параллельно и присматривает за ними: сбой
  одного записывается в журнал, компонент перезапускается, второй продолжает работать.
  См. [ADR-0003](../decisions/0003-single-process-supervised.md).

## Интерфейсы

- Модуль операций — бизнес-ядро для групп API: определение приложения по ключу,
  идемпотентная выдача привязок (с переиспользованием индекса деривации между сетями
  одного кошелька), адреса, балансы (поступило + ожидается), история входящих,
  пользователи приложения.
- Супервизор — один процесс (ADR-0003): API-сервер и цикл watcher — параллельные задачи;
  падение любой журналируется и перезапускается, не задевая вторую.
- Консольная команда `seedrays serve` — мигрирует базы и запускает шлюз; каталог данных и
  адрес — из `SEEDRAYS_DATA_DIR` и `SEEDRAYS_BIND` (развёрточный уровень
  [ADR-0016](../decisions/0016-config-layers.md)).
