# Watcher

Наблюдает за балансами и входящими платежами по кошелькам всех пользователей.

## Устройство

Построен по принципу «library-first» (см. [ADR-0001](../decisions/0001-library-first-core.md)):

- **Один проход** — базовая операция: опросить источник данных по отслеживаемым адресам,
  зафиксировать новые поступления и изменения балансов.
- **Постоянный режим** — цикл, вызывающий «один проход» с заданным интервалом; работает
  фоновым потоком/задачей, которую запускает и контролирует [оркестратор](orchestrator.md)
  (см. [ADR-0003](../decisions/0003-single-process-supervised.md)).
- **Консольная команда** — разовая проверка для отладки и ручного контроля, использующая тот
  же код «одного прохода».

## Многопользовательский проход

Watcher мыслит адресами, а не пользователями
(см. [ADR-0007](../decisions/0007-address-centric-watcher.md)), а данные снимает
диапазонами, а не по адресам (см. [ADR-0018](../decisions/0018-range-scanning.md)):

- Перед проходом он собирает множество привязок всех пользователей; каждая запись помечена
  владельцем (пользователь, кошелёк) и сетью. Это множество — **локальный фильтр
  сопоставления**.
- По каждой сети проход один раз запрашивает голову цепочки и границу финальности, затем
  сканирует в две фазы (см. [ADR-0021](../decisions/0021-two-phase-scanning.md)) —
  стоимость не зависит от числа адресов; переводы сопоставляются с множеством привязок
  локально, и провайдер список адресов шлюза не узнаёт:
  - **авторитетное сканирование** читает только финализированную зону (нативные блоки до
    границы, токен-события «только подтверждённые») от своих курсоров; его строки несут
    отметку финализации и являются единственным источником изменений баланса —
    финализированная успешная строка учитывается в балансе одной транзакцией БД вместе
    со своей отметкой;
  - **предварительный показ** читает зону выше границы, чтобы платёж был виден как
    ожидающий сразу; его строки предварительные, и когда финализированная зона позже
    накрывает их блоки, они либо продвигаются, либо — если перестроившаяся цепь их так
    и не подтвердила — удаляются с предупреждением в журнале.
- По-адресные проиндексированные запросы остаются для точечных задач: первичная история
  новой привязки, выборочная сверка.
- Догон после простоя ограничен на каждый проход: нативный скан — потолком блоков,
  токен-скан — окном времени; курсоры двигаются ограниченными шагами, поэтому трафик к
  провайдеру и память одного прохода предсказуемы, а прогресс фиксируется каждым
  проходом (пока токен-скан догоняет, чистка токен-строк после реорганизаций
  откладывается — их подтверждение ещё впереди).
- Ошибки изолируются внутри прохода и журналируются: ответ провайдера «сбавь темп»
  приостанавливает сканирование этой сети до следующего прохода; сбой базы одного
  пользователя исключает этого владельца до конца прохода, не останавливая остальных;
  испорченная числовая/датовая настройка деградирует к значению по умолчанию с
  ошибкой в журнале.
- Результаты раскладываются по базам владельцев через [слой хранения](storage.md).

## Доступ к данным

Весь доступ к блокчейну идёт через [абстракцию блокчейна](chain-abstraction.md): сначала
публичные API провайдеров, позже — своя развёрнутая нода (RPC) — без изменений в логике
watcher.

Служебное состояние watcher — курсоры авторитетного сканирования по каждой сети
(последний обработанный финализированный блок и временной курсор скана токенов) —
хранится в общей реестровой базе: это точка возобновления сканирования после остановки
(см. [ADR-0010](../decisions/0010-networks-assets-financial-data.md),
[ADR-0021](../decisions/0021-two-phase-scanning.md)). Зона предпросмотра курсора не
имеет — каждый проход пересканирует её целиком.

## Интерфейсы

- Модуль: «один проход» (`run_pass`) и постоянный цикл поверх него; цикл запускает и
  контролирует оркестратор.
- Консольная команда `seedrays watch` — разовый проход; каталог данных — из
  конфигурационного файла шлюза (развёрточный уровень
  [ADR-0016](../decisions/0016-config-layers.md) и
  [ADR-0026](../decisions/0026-configuration-file.md)).
- Настройки (реестр): ключ провайдера и темп запросов, интервал прохода, перекрытие
  курсора, момент начала сканирования и наблюдаемые токен-контракты по сетям
  (`watcher.contracts.<сеть>` — JSON-список записей контракт/символ/десятичность).
- Первый проход по сети сканирует от первого запуска шлюза — операции, случившиеся до
  существования шлюза, ему не интересны; настройка `watcher.scan_start` явно
  переопределяет это.
