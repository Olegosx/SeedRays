# Словарь терминов

Термины, используемые в документации проекта.

## Термины

| Термин | Определение |
|--------|-------------|
| ADR | Architecture Decision Record — короткий документ, фиксирующий одно архитектурное решение: контекст, рассмотренные варианты, выбор и последствия. |
| API-ключ | Секретный идентификатор, который приложение предъявляет для доступа к API приложений. |
| BIP32 | Стандарт, описывающий иерархические детерминированные (HD) кошельки и деривацию ключей. |
| Актив | Сетеспецифичная единица ценности: нативная монета сети или токен, определяемый своим контрактом в этой сети. USDT в TRON и USDT в Ethereum — два разных актива. |
| Вендоринг | Хранение сторонней библиотеки просмотренным файлом фиксированной версии прямо в репозитории проекта — вместо подтягивания из реестра пакетов. |
| ES-модули | Встроенная в браузеры система модулей JavaScript: файлы импортируют друг друга напрямую, сборщик не требуется. |
| Деривация | Вычисление дочерних ключей и адресов из родительского ключа по BIP32. |
| HD-кошелёк | Иерархический детерминированный кошелёк — всё дерево его ключей и адресов выводится из одного сида. |
| Кодовая фраза (passphrase) | Необязательный дополнительный секрет BIP39: одна и та же сид-фраза с другой кодовой фразой открывает совершенно другой кошелёк; забытая кодовая фраза — навсегда потерянные средства. |
| Мемо | Метка, прикрепляемая к транзакции в некоторых сетях (например, TON); позволяет многим плательщикам использовать один адрес, различаясь по мемо. |
| Миграция схемы | Управляемое изменение структуры базы данных (таблиц, колонок) при обновлении шлюза; прогоняется по всем пользовательским базам. |
| Привязка | Постоянное соответствие «кошелёк + сеть + приложение + пользователь приложения → платёжный адрес (+ мемо)» — основная сущность шлюза в главном режиме работы. |
| Приложение | Внешняя система, подключённая к шлюзу; принадлежит пользователю шлюза, идентифицируется своим API-ключом, имеет собственных пользователей. |
| Семейство кошелька | Стандарт адресов и деривации, которому следует кошелёк (TRON, EVM, …); один EVM-кошелёк даёт адреса, действительные во всех EVM-сетях. |
| RPC | Интерфейс удалённых вызовов ноды блокчейна; используется для запроса данных цепочки напрямую со своей развёрнутой ноды. |
| Сид-фраза | Человекочитаемая запись сида кошелька; тот, кто её знает, распоряжается средствами. |
| WAL | Write-ahead logging (журнал с упреждающей записью) — режим журнала SQLite, при котором читатели не блокируются писателем. |
| Watch-only | Наблюдающий режим работы: доступны только публичные ключи и адреса — выводить адреса и наблюдать можно, подписывать нельзя. |
| Watcher | Компонент шлюза, наблюдающий за балансами и входящими платежами. |
| Webhook | Уведомление обратным вызовом: шлюз сам обращается по URL, зарегистрированному приложением, при наступлении события (например, новом поступлении). Запланированное расширение. |
| xpub | Расширенный публичный ключ — позволяет вывести все адреса кошелька без доступа к приватным ключам. |
