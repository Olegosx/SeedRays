# Сценарии панели оператора

Сценарии работы оператора шлюза (суперадмина) в панели управления: управление
пользователями и общими настройками шлюза.

## Учётная запись оператора и вход

- Регистрации операторов не существует: учётная запись создаётся консольной командой
  `seedrays operator-create --login …` на сервере (пароль — скрытым интерактивным
  вводом). Кто имеет доступ к консоли сервера — тот и создаёт операторов.
- Вход — отдельная страница; сессия панели живёт в собственной куке, отдельной от
  кабинета пользователя (структурная граница ADR-0004), срок — 1 день. Вход ограничен
  тем же тормозом перебора и той же невидимой proof-of-work капчей
  ([ADR-0022](../20-architecture/decisions/0022-pow-captcha.md)), что и кабинет.
- Смена пароля оператора — на странице настроек; смена гасит остальные сессии оператора.

## Структура панели

Боковое меню из трёх разделов — «Пользователи», «Счета» и «Настройки»; верхняя панель
та же, что в кабинете (переключатель языка, меню оператора с выходом).

## Пользователи

- Таблица пользователей шлюза: имя, почты (с пометкой неподтверждённых), статус
  (активен / заблокирован), число кошельков (у нечитаемой базы — «—»), дата создания.
- **Блокировка** — через подтверждающий диалог: пользователь и все его приложения
  немедленно теряют доступ, сессии завершаются. Разблокировка — одним действием.
- **Сброс пароля** — запасной путь восстановления из сценария кабинета: по
  подтверждению генерируется временный пароль и показывается ровно один раз; все сессии
  пользователя завершаются; пароль передаётся пользователю вне шлюза.
- **Удаление** ([ADR-0024](../20-architecture/decisions/0024-user-deletion-archive.md)) —
  только для заблокированного пользователя (кнопка появляется после блокировки);
  в подтверждающем диалоге логин удаляемого набирается руками, и сервер сверяет его
  ещё раз. Данные не стираются, а переезжают в архив `archive/` каталога данных
  (снимок строк реестра + каталог пользователя с базой); имя, почты, xpub и ключи API
  освобождаются. Восстановление — консольной командой `seedrays user-restore
  --archive …` на сервере; статус возвращается как был («заблокирован»),
  разблокировка — отдельным действием в панели.

## Счета

Раздел о вознаграждении владельца шлюза: чем пользователи платят и что с этими платежами
происходит.

- **Мастер-кошельки** по сетям оплаты: наблюдающий xpub уровня аккаунта, из которого
  каждому пользователю выдаётся постоянный адрес для оплаты счетов. Ключ проверяется так
  же, как кошелёк пользователя, включая уникальность по всему шлюзу. Сеть без внесённого
  кошелька пользователю для оплаты не предлагается, и счёт в ней не выставляется —
  оператор об этом уведомляется.
- **Счета всех пользователей**: пользователь, период, оборот, сумма, срок, состояние,
  зачтённая сумма; фильтр по состоянию.
- **Ручное подтверждение оплаты** — для денег, пришедших мимо шлюза: подтверждающий
  диалог с обязательной причиной. Результат тот же, что у зачтённого платежа —
  приостановленный доступ открывается. Событие попадает в журнал безопасности
  ([ADR-0023](../20-architecture/decisions/0023-security-journal.md)) рядом с
  блокировками и сбросами паролей.
- Пользователи, приостановленные за неуплату, помечаются и в списке пользователей —
  отдельно от административной блокировки, потому что это разные решения и снимаются они
  по-разному.

## Настройки

Формы поверх таблицы `settings` реестра ([ADR-0016](../20-architecture/decisions/0016-config-layers.md)):

- **Провайдер TRON (TronGrid)**: ключ API, темп запросов.
- **Почта (Resend, [ADR-0020](../20-architecture/decisions/0020-mail-provider.md))**:
  ключ API, адрес отправителя, базовый адрес шлюза для ссылок в письмах, флаг режима
  разработки (авто-подтверждение почты без писем).
- **Watcher**: интервал прохода, перекрытие сканирования. Список наблюдаемых
  токен-контрактов (`watcher.contracts.<сеть>`) панелью не редактируется — решение
  владельца, настройка вносится вручную.
- **Сеть и развёртывание**: доверенные обратные прокси (`gateway.trusted_proxies` —
  адреса и CIDR-диапазоны через запятую; например, адрес своего nginx/Apache,
  диапазоны Cloudflare). У соединений с перечисленных прокси шлюз берёт IP посетителя
  из `X-Forwarded-For` — тормоз перебора и журнал безопасности видят реальные адреса;
  пусто — доверие только 127.0.0.1. Применяется после перезапуска.
- **Вознаграждение шлюза ([ADR-0027](../20-architecture/decisions/0027-gateway-fee-billing.md))**:
  включение (по умолчанию выключено — установка не должна начать выставлять счета сама),
  ставка в процентах, порог оборота в USDT, срок оплаты в днях, список
  активов оборота и активов оплаты по сетям (списки адресов контрактов в формате JSON) и
  параметры уведомлений. Списки проверяются при сохранении так же, как числовые поля:
  опечатка отвергается целиком, иначе оборот молча перестал бы считаться. Ставка
  принимает не более двух знаков после запятой, и значение точнее отвергается по той же
  причине: ставка, которую не держит арифметика, сделала бы счёт противоречащим себе.
- **Журнал безопасности ([ADR-0023](../20-architecture/decisions/0023-security-journal.md))**:
  размер файла до ротации (МБ) и число хранимых сжатых архивов; применяется после
  перезапуска шлюза. Сам журнал читается на сервере (`logs/security.log` в каталоге
  данных) — экрана журнала в панели нет.
- Секретные значения (ключи API) наружу не возвращаются никогда: форма показывает
  только признак «настроен / не настроен»; пустое поле секрета при сохранении означает
  «не менять».
- Пустое несекретное поле означает «настройка снята»: читатель берёт своё значение по
  умолчанию, а не считает пустоту испорченным значением.
- Числовые поля (темп запросов, интервал и перекрытие watcher, размер и число архивов
  журнала) проверяются при сохранении — интервалы и темп принимают неотрицательное
  число, поля журнала — целое от единицы. Негодное значение отклоняется целиком, вместе
  со всей отправленной формой: половина сохранённых настроек хуже отказа. Проверяет и
  форма (подсвечивает поле сразу), и сервер — источником правды остаётся сервер.
- Ниже — состояние watcher по сетям (только чтение): последний обработанный блок и
  время последнего прохода.
